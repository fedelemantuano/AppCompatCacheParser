# JSON output design

The output contract was confirmed on 2026-10-09.

## Confirmed requirements

- Export one compact JSON object per line (JSON Lines), with one object for each CSV data row and no header object or enclosing array.
- JSON field names match the CSV column names exactly: `ControlSet`, `CacheEntryPosition`, `Path`, `LastModifiedTimeUTC`, `Executed`, `Duplicate`, `SourceFile`.
- Export the same records and field meanings as CSV; do not add internal binary data or additional properties from the cache-entry model.
- Leave CSV output and its custom `--dt` formatting unchanged.
- JSON timestamps use ISO 8601 in UTC with the `Z` suffix, independent of `--dt`, preserving all seven available fractional-second digits.
- A missing timestamp is JSON `null`.
- At least one output directory is required: `--csv`, `--json`, or both. JSON-only export does not require `--csv`.
- `--jsonf` selects the JSON filename independently of `--csvf`; missing output directories are created.
- `ControlSet` and `CacheEntryPosition` are JSON numbers; `Duplicate` is a JSON boolean; `Executed` is a string containing the CSV label (`Yes`, `No`, or `NA`); `Path` and `SourceFile` are strings.
- The automatic JSON filename uses the same naming scheme as CSV with a `.json` extension. Custom CSV names do not affect automatic JSON names.
- `--jsonf` uses the supplied basename, following the existing `--csvf` convention.
- Existing JSON files are replaced completely, without appending records or retaining trailing content.
- A successful parse with no cache entries creates an empty JSON Lines file.

## Verified reference behavior

[MFTECmd](https://github.com/EricZimmerman/MFTECmd/blob/master/MFTECmd/Program.cs) provides `--json` for the output directory and `--jsonf` for a custom filename. Its JSON export writes one serialized record per line to a `.json` file and sets `DateHandler.ISO8601`.

[Elasticsearch date documentation](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/date) includes timestamps ending in `Z` as valid input for the default date mapping. `Z` denotes UTC; an explicit UTC offset is another representation of the same time zone. JSON serialization precision and indexed precision are separate: Elasticsearch `date` indexes milliseconds, whereas [date_nanos](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/date_nanos) supports finer precision with a more limited date range.

## Timestamp example

`"LastModifiedTimeUTC":"2026-10-09T10:20:30.1234567Z"`

## Validation

Verified locally on 2026-10-09:

- Release builds for `net472` and `net9.0`: no warnings or errors.
- Solution test command: 21 output regression cases passed, including CSV/JSON equivalence for all eight bundled Windows cache samples.
- Compiled CLI help exposes `--json` and `--jsonf` with CSV-only, JSON-only, and combined examples.
- A temporary Elasticsearch 9.2.0 instance accepted three records generated by the compiled writer under a default `date` mapping: an offset-normalized UTC timestamp with seven fractional-second digits, an explicit null timestamp, and a timestamp in 1601. `_source` retained `2026-10-09T10:20:30.1234567Z`; the indexed date was returned as `2026-10-09T10:20:30.123Z`.

These checks cover output serialization and bundled cache samples. Live Windows Registry access was not exercised.
